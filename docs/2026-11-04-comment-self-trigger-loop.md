# 事故复盘：评论触发工作流的自触发循环

## 结论

一次自动化评论流程把命令文本写进了普通说明评论，触发规则又使用全文匹配，导致失败评论反复触发同一个工作流。事故影响了一个 PR 的评论区和 Actions 运行，没有证据表明仓库内容或测试 Key 泄露。

## 根因

三个条件同时出现：

1. 触发规则把普通评论中的命令文本当成命令。
2. 自动评论正文包含了这个命令文本。
3. 自动评论使用了会再次产生评论事件的身份。

结果形成：

```text
校验失败
  → 自动发布失败说明
  → 失败说明再次命中触发规则
  → 工作流重新运行
  → 再次发布失败说明
```

## 修复

- 命令触发改为只接受评论开头的精确命令。
- 自动化评论不再被当作用户命令。
- 结果评论使用固定标记就地更新，避免每轮新增评论。
- 同一个 PR 的检查串行执行。
- 自动回贴报告时对命令文本做额外隔离处理。
- 触发失败或收到限流响应时停止继续发送评论。

## 后续规则

任何“评论触发工作流”的实现都必须满足：

- 命令使用精确匹配，不使用全文包含匹配。
- 机器人评论不能触发用户命令路径。
- 结果评论必须幂等更新。
- 每个 PR 或 Issue 必须有并发收口。
- 遇到限流、权限错误或上游失败时必须停止重试，并保留人工处理路径。
- 自动评论正文不要以触发命令开头。

## 证据边界

这次事故复盘只保留流程根因和修复原则，不公开账号身份、凭证类型、限流配额、内部部署位置或运维路径。
