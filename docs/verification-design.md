# RelayQuality 验证架构说明

RelayQuality 是一个免费的、开放的 Claude Code / Anthropic 兼容中转站质量测试服务。项目不收广告费、不做 AFF、不接受付费置顶，也不出售“验证通过”。

测量在提交者自己的机器上发生，仓库只负责核验证据和呈现结果。

GitHub PR 提交公开的服务商资料；提交者本地运行 MQ 引擎并把报告贴进 PR；
GitHub Actions 核验报告与条目声明是否一致，据此决定能否自动合并。

## 公共流程

```text
服务商作者提交 providers/<id>.json
  → Action 检查字段、URL、推广参数，并发布「怎么跑 MQ」的指引评论
  → 作者在自己的机器上运行 mq.py（Key 不离开本机）
  → 报告全文贴进 PR 评论（首行含 <!--MQ-REPORT:...--> 机器可读块）
  → 作者评论 /mq-done
  → Action 核验：报告存在 / host 与 api_base 一致 / 30 天内 / 结论合格
  → 四项全过才自动合并；合并后回写 verification 字段
```

核验规则与设计取舍见 [2026-11-04-mq-report-gate.md](2026-11-04-mq-report-gate.md)。

## 测量内容

MQ 引擎检查 Anthropic Messages 兼容接口的公开行为，包括：

- 模型目录：声明模型是否存在、目录家族构成
- 与上一次测试的目录差异（新增/消失模型、家族构成翻转）
- 基础 Messages 响应结构
- SSE 流式事件顺序
- system 指令透传
- tool_use 与 tool_result 闭环
- 重复请求的 usage 一致性
- `count_tokens` 固定文本指纹
- extended thinking 字段存在性
- 模型自述（仅记录，不参与判定）
- 多次请求的成功率、延迟和流速

这些检查只描述指定时间、指定端点和指定模型的测试结果。

## Key 处理边界

**本仓库不接收 Key。** MQ 引擎在提交者自己的机器上运行，测试 Key 从未离开本机，
也不会出现在 PR、报告或任何仓库文件中。报告里的所有证据片段都经过脱敏。

RelayQuality 不能证明服务商不会留存或转卖请求，也不能通过短时黑盒测试证明底层模型一定是真实 Claude。`basic_passed` 只表示基础协议探针在本次采样中通过。

## 端点一致性

验证任务使用 PR 中声明的 `api_base`。如果实际测试端点与 PR 声明不一致，结果不能作为该 PR 的验证结果。这样可以避免“测试一个端点、收录另一个端点”。

## 公开 API

```text
GET  /api/prs                 公开的待验证 PR 列表，不含 Key
GET  /pr/<PR号>               某个 PR 的专属验证工作台
GET  /reports/<PR号>/<报告>   脱敏后的验证报告
GET  /healthz                 服务健康状态
```

内部认证、部署位置、凭证名称和运维步骤不写入公开文档。需要维护服务时，使用受控的内部运维记录。

## 结果边界

验证结果是快照证据，不是安全背书、合规认证、模型真实性证明或商业推荐。用户应在自己的环境中使用 `mq/mq.py` 重跑，并避免把敏感代码和密钥交给任何第三方中转站。
